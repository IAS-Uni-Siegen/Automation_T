\begin{frame}{Types of Processors used in Automation Systems}
    What is a Processor?
    \begin{itemize}
        \item A processor is an electronic component that executes instructions to perform tasks.
        \item It serves as the "brain" of an automation system, processing data and controlling operations.
        \item Processors can vary in complexity, speed, and functionality depending on the application.
        \item They are essential for executing control algorithms, managing communication, and interfacing with sensors and actuators.
    \end{itemize}
Types of Processors:
    \begin{itemize}
        \item Microcontrollers (MCUs)
        \item Digital Signal Processors (DSPs)
        \item Field-Programmable Gate Arrays (FPGAs)
        \item Application-Specific Integrated Circuits (ASICs)
        \item Programmable Logic Controllers (PLCs)
    \end{itemize}

\end{frame}

\begin{frame}{Introduction to basics of Industrial Automation}
\textbf{Terms}
\begin{enumerate}
    \item \textbf{Logic Control} -  assigns certain logic states of the output signals to certain states of the
 input signals with the help of boolean operations.
    \item \textbf{Sequence Control} - a control method with an inevitably stepwise sequence, in which the
 transition from one step to the following step(s) according to the program takes place
 depending of transition conditions.
    \item \textbf{Program of a Control} - Complete set of instructions and declarations to process signals and 
control a system (or plant) so it behaves as required.
\end{enumerate}
\textit{Remark}: This definition is valid independently of the signal processing being
 connection oriented or memory programmed.
\end{frame}

\begin{frame}{Definitions regarding program implementation}
\begin{enumerate}
    \item \textbf{Connection oriented control} - control program is defined by the
    type of the functional units and by their  connections.
    \begin{itemize}
        \item \textbf{Control with fixed program} - a connection oriented control, where program
        modifications are not planned.
        \item \textbf{Reprogrammable control} - a connection oriented control, where program
        modifications are provided for and are easy to carry out.
    \end{itemize}

    \item \textbf{Programmable logic control} - control program is stored in a
    program memory.
    \begin{itemize}
        \item \textbf{Freely programmable control} - a programmable logic control with read/write
        memory (RAM) as programm memory, whose entire content can be modified even in
        arbitrarily small extent without mechanical intervention into the control device.
        \item \textbf{Control with replaceable program} - a programmable logic control with read-only
        memory (ROM) as program memory, whose content can be modified after programming being once completed 
        only by a mechanical intervention into the control device.
    \end{itemize}
\end{enumerate}
\end{frame}

\begin{frame}{Definitions regarding control hierarchy}
\begin{enumerate}
    \item \textbf{Individual control, drive control} – a functional unit for the control of a 
    single control element or a drive.
    \begin{itemize}
        \item \textbf{Individual control level, drive control level} – summarizes all parts 
        of a control system that act directly on the process 
        by means of final control elements or drives.
    \end{itemize}

    \item \textbf{Group control} – a functional unit for the control of a 
    coherent process part, which is above associated individual or drive controls.
    \begin{itemize}
        \item \textbf{Group control level} – summarizes all parts of 
        the control unit that act on certain partitions of the individual control level.  
    \end{itemize}

    \item \textbf{Process control} – a functional unit above the 
    the group controls responsible for the control of the entire process.
    \begin{itemize}
        \item \textbf{Process control level} – summarizes all parts of 
        the control unit that act on the group control level.
    \end{itemize}
\end{enumerate}
\end{frame}


\begin{frame}{Software of PLC devices}
    \textbf{Organization of operational software}\\
    For structuring of the software in PLC devices so called blocks or program organization
    entities (POEs) are employed. 
    The block types are separated into
    \begin{itemize}
        \item  Organizational blocks (OB)
        \item Function blocks (FB) and functions (FC)
        \item Data blocks (DB)
        \item System functions (SFC) and system function blocks (SFB)
    \end{itemize}
    A block is a part of the application program grouped by function, structure, 
    or purpose. There are:
    \begin{itemize}
      \item Code blocks (OBs, FCs, FBs) that contain instructions for data processing
      \item Data blocks (DBs) that store data
    \end{itemize}
    Some organizational blocks (OBs) form the interface between the application program and 
    the system program. They are triggered by the system and contain user-written code. 
    By placing code in specific OBs, the user determines whether it runs cyclically, on a 
    timer, or in response to an alarm.
\end{frame}


\begin{frame}{Cyclic Processing in PLC}
    \begin{columns}
    \column{0.5\textwidth}
    In a programmable logic controller (PLC), the program usually runs in a cycle (loop).
    \begin{itemize}
        \item PLC programs normally run in a \textbf{cyclic loop}.
        \item After switching on, the PLC executes a \textbf{start-up block} once.
    \end{itemize}

    \vspace{0.3cm}

    \textbf{Cyclic Program Scan}
    \begin{enumerate}
        \item Start at the \textbf{top of the main program} (e.g., Siemens: OB1).
        \item Execute each instruction \textbf{sequentially} to the end.
        \item Run internal \textbf{system routines}.
        \item Restart from the \textbf{top of the program}.
    \end{enumerate}

\begin{frame}{Cyclic Processing in PLC}
    \textbf{Program Blocks}
    \begin{itemize}
        \item Functions and function blocks can be called inside the main block.
        \item Nested calls are possible (depth depends on the PLC manufacturer).
    \end{itemize}

    \vspace{0.3cm}

    \textbf{Processing Time (Scan Time)}
    \begin{itemize}
        \item Total cycle time = sum of processing times of all called blocks.
        \item If a block is called $n$ times, its time is counted $n$ times.
    \end{itemize}
\end{frame}


\begin{frame}{Program Blocks Overview}
\begin{enumerate}
    \item \textbf{Organizational Blocks (OBs)}  
    Interface between system program and application program. They are called by the operating system and determine:
    cyclical and alarm-controlled execution, startup behavior, error handling.
    OBs are divided into:
    \begin{itemize}
        \item \textbf{System-called OBs}: control program flow, startup, and error response; user programs these.
        \item \textbf{Integrated special functions}: built-in system functions called when needed by the application.
    \end{itemize}

    \item \textbf{Functions (FCs)}  
    Code blocks \emph{without memory}. They are parameterizable and return a value to the calling block.

    \item \textbf{Function Blocks (FBs)}  
    Code blocks \emph{with memory}. Used for recurring or complex tasks (e.g., digital logic, sequences, closed-loop control). They can be called multiple times with different parameters.

    \item \textbf{Data Blocks (DBs)}  
    Contain fixed or variable data used by the program. They hold no executable code. Data may include:
    bit patterns, numeric values, text, various data types.

    \item \textbf{System Functions (SFCs) and System Function Blocks (SFBs)}  
    Prefabricated operating-system blocks for tasks such as communication or built-in system operations.
\end{enumerate}
\end{frame}

\begin{frame}{Interrupts in Cyclical Processing}
    \textbf{Cyclical program processing can be interrupted by:}
        \begin{itemize}
            \item \textbf{Alarm processing}
                  \begin{itemize}
                  \item The normal cycle is interrupted by an external or internal interrupt signal.
                  \item The PLC executes a special block (Interrupt Service Routine).
                  \item Allows immediate reaction to important process events.
                  \item After finishing, the PLC returns to the point where it was interrupted.
                  \end{itemize}
            \item \textbf{Time-controlled processing}
                  \begin{itemize}
                  \item An internal clock triggers an interrupt at defined time intervals.
                  \item The PLC runs a specific time-controlled program block.
                  \item After execution, the PLC returns to the normal cycle.
                  \item Often used in closed-loop control tasks requiring precise timing.
                  \end{itemize}
            \item \textbf{Programming failures and device failures}
            \item \textbf{Signals from the hardware}
            \item \textbf{Change of mode of operation} 
            \begin{itemize}
                \item Caused by the device's mode switch
                \item Or by the programming tool
            \end{itemize}
        \end{itemize}
\end{frame}


\begin{frame}{Process Image Table}
    \textbf{Process Image of Inputs (PII)}
    \begin{itemize}
        \item At the start of every cycle, all input states are scanned.
        \item These values are stored in the Process Image Input table.
        \item During program execution, the PLC uses the stored values.
        \item Ensures consistent input data throughout the cycle.
    \end{itemize}

    \vspace{0.3cm}

    \textbf{Process Image of Outputs (PIO)}
    \begin{itemize}
        \item Output values written by the program are stored in the PIO table.
        \item At the end of the cycle, the table is copied to actual outputs.
        \item Then a new cycle begins.
    \end{itemize}
\end{frame}

\begin{frame}{RS Flip-Flop}

\textbf{RS Flip-Flop:}
    \begin{columns}
    \column{0.55\textwidth}
    A R/S flip flop is a storing function with two input variables R and S and an output variable
    Q, where the value Q = 1  belongs to the input states R = 0 and S = 1 and Q = 0 belongs to
    the input states R = 1 and S = 0

    \vspace{0.3cm}
    \centering
          \begin{tabular}{c c c}
          \hline
          R & S & $Q_{k+1}$ \\
          \hline
          0 & 0 & $Q_k$ \\
          0 & 1 & 1 \\
          1 & 0 & 0 \\
          1 & 1 & 0 (R has priority) \\
          \hline
        \end{tabular}

    \column{0.5\textwidth}
    \centering

\begin{frame}{RS Flip-Flop}
    \begin{columns}
    \column{0.55\textwidth}
    \textbf{Priority rules:}
    \begin{itemize}
        \item If \textbf{R has priority}: $R=1$ dominates and forces $Q=0$.
        \item If \textbf{S has priority}: $S=1$ dominates and forces $Q=1$.
    \end{itemize}

    \vspace{0.3cm}

    \textbf{In PLC software:}
    \begin{itemize}
        \item Priority is determined by the \textbf{order of instructions}.
        \item The instruction processed \textbf{last} determines the final result.
    \end{itemize}

\begin{frame}{Compare and Arithmetic Operations}
\footnotesize
\begin{itemize}
    \item \textbf{Compare operations:} $<$, $>$, $\leq$, $\geq$, ==, $\neq$
    \begin{itemize}
        \item Result: Boolean variable
        \item Can be used in binary operations or control program flow
    \end{itemize}
    \item \textbf{Basic arithmetic:} ADD, SUB, MUL, DIV
    \begin{itemize}
        \item SIEMENS: $+$, $-$, $*$, $/$ with type specifier: I (INT), D (DINT), R (REAL)
        \item Fixed-point multiplication: width doubles (INT 16-bit $\times$ INT 16-bit $\rightarrow$ DINT 32-bit)
        \item Division: result type = Dividend type
        \item Floating point: watch exponent overflow
        \item Always handle division by 0
    \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Load, Assignment and Organizational Functions}
\footnotesize
\begin{itemize}
    \item \textbf{Load operations:} L or LD
    \begin{itemize}
        \item Provides input variable for an operation
    \end{itemize}
    \item \textbf{Assignment / Transfer:} T or ST
    \begin{itemize}
        \item Assign value to a variable, e.g., accumulator
        \item Can also be implemented with `=`
    \end{itemize}
    \item \textbf{Organizational functions:} Branching
    \begin{itemize}
        \item Conditional/unconditional based on RLO or internal status
        \item Syntax examples: SPA [label], SPB [label], SPO [label]
    \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Shift Functions and Type Conversions}
\footnotesize
\begin{itemize}
    \item \textbf{Shift and rotate operations:}
    \begin{itemize}
        \item Shift left/right, rotate left/right on accumulator or memory
        \item Examples: SLW 3 (shift left 3), SRW 5 (shift right 5), RLD 6 (rotate left 6)
    \end{itemize}
    \item \textbf{Type conversions:}
    \begin{itemize}
        \item BTI: BCD $\rightarrow$ INT
        \item ITB: INT $\rightarrow$ BCD
        \item DTR: Fixed-point $\rightarrow$ Floating-point
        \item RND: Floating-point $\rightarrow$ Fixed-point
    \end{itemize}
\end{itemize}
\end{frame}


\begin{frame}{Statement List (STL) - Control Statements}
\footnotesize
\begin{itemize}
    \item A statement list consists of multiple control statements.
    \item Each control statement:
    \begin{itemize}
        \item Starts on a new line
        \item Contains an \textbf{operator} (optionally with a modifier)
        \item May contain one or more operands, separated by commas
        \item May include a preceding label followed by a colon (:)
        \item May include a comment at the end of the line
    \end{itemize}
    \item Blank lines can be inserted between statements
    \item For binary operands, the pre-occupation of RLO can be done by the first statement of an AND or OR operation
    \item \textbf{Note:} Nested logic (use of `(` and `)`) requires a stack of RLOs
\end{itemize}
\end{frame}

\begin{frame}{Operations, Modifiers, and Operands}
\footnotesize
\begin{itemize}
    \item Default semantics: 
    \[
    \text{RLO} = \text{RLO OP Operand}
    \]
    where RLO = result of the preceding logic operation.
    \item Example: 
    \begin{itemize}
        \item Statement: \texttt{A "Value"}  
        \item Interpreted as: \texttt{RLO = RLO AND "Value"}
    \end{itemize}
    \item Modifier \texttt{N}: boolean negation of the operand
    \begin{itemize}
        \item Statement: \texttt{AN "INPUT\_1"}  
        \item Interpreted as: \texttt{RLO = RLO AND NOT("INPUT\_1")}
    \end{itemize}
    \item Modifier \texttt{(}: suspend processing until \texttt{)} occurs
    \begin{itemize}
        \item Statements: \\
        \texttt{A(} \newline
        \texttt{O "INPUT\_2"} \newline
        \texttt{O "INPUT\_3"} \newline
        \texttt{)}
        \item Interpreted as: \texttt{RLO = RLO AND ("INPUT\_2" OR "INPUT\_3")}
    \end{itemize}
    \item Modifier \texttt{C} (conditionally): statement processed only if previous RLO = 1 (or 0 if combined with N-modifier)
\end{itemize}
\end{frame}

\begin{frame}{LAD (Ladder Diagram)}
\footnotesize
\begin{itemize}
    \item A \textbf{LAD program} provides processing, testing, and modification of data using standardized graphical symbols.
    \item These symbols are arranged in \textbf{networks} that resemble the rungs of a relay logic diagram.
    \item LAD networks are bounded on the left and right by \textbf{conductor rails}.
\end{itemize}
\end{frame}


\begin{frame}{Conductor Rails and Connection Elements}
\footnotesize
\begin{itemize}
    \item A LAD network is bounded by vertical lines called \textbf{conductor rails}:
    \begin{itemize}
        \item \textbf{Left conductor rail}: mandatory, state is \textbf{ON} unless connected to an inactive step
        \item \textbf{Right conductor rail}: optional, no defined state
    \end{itemize}
    \item \textbf{Connection elements} are horizontal or vertical lines:
    \begin{itemize}
        \item States: \textbf{ON} (1) or \textbf{OFF} (0)
        \item \textbf{Horizontal lines}: transfer state from left to right
        \item \textbf{Vertical lines}: state = OR of all connected left horizontal lines
        \begin{itemize}
            \item \textbf{OFF}: all left lines OFF
            \item \textbf{ON}: at least one left line ON
        \end{itemize}
        \item Vertical line state determines all horizontal lines on the right
        \item States are \textbf{not copied} to lines on the left
    \end{itemize}
\end{itemize}
\end{frame}


\begin{frame}{Scan Operations and Assignment Operations}
\footnotesize
\begin{itemize}
    \item \textbf{Scan Operations (Contacts)}:
    \begin{itemize}
        \item Pass the state of the horizontal connection on the left to the right.
        \item Only passes the state if the associated boolean input, output, or memory variable is \textbf{ON}.
        \item Does \textbf{not} change the state of the boolean variable itself.
    \end{itemize}
    \item \textbf{Assignment Operations (Coils)}:
    \begin{itemize}
        \item Copy the state of the left-hand connection to the right-hand connection.
        \item Update the associated boolean variable with the left-hand connection state.
        \item No modification to the signal occurs; the coil reflects the left-hand state.
    \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Sequential Function Chart (SFC) Overview}
\begin{columns}
    \column{0.5\textwidth}
    \footnotesize
    \begin{itemize}
        \item SFC subdivides a PLC program into \textbf{Steps} and \textbf{Transitions}.
        \item Steps and transitions are connected by \textbf{directional connections}.
        \item Each step has a set of \textbf{Actions}; each transition has a \textbf{Transition Condition}.
    \end{itemize}
    \column{0.5\textwidth}
    \begin{figure}[h]
    \centering
    \includegraphics[scale=0.35]{fig/lec04/SFC_chart_1.pdf}
    \caption*{SFC Step and Initial step in S7 Graph}
    \end{figure}
\end{columns}
\end{frame}

\begin{frame}{Steps}
\footnotesize
\begin{itemize}
    \item A step defines behavior of the program for given inputs/outputs via its \textbf{actions}.
    \item A step is either \textbf{active} or \textbf{inactive}.
    \item Step representation:
    \begin{itemize}
        \item Symbol containing the Step name
        \item Incoming directional connection at the top
        \item Outgoing directional connections at the bottom
    \end{itemize}
    \item Step flag: boolean variable (\textbf{1 = active}, \textbf{0 = inactive}).
    \item Initial steps determine the program's starting state (may be marked with twin lines).
\end{itemize}
\end{frame}


\begin{frame}{Transitions}
\footnotesize
\begin{itemize}
    \item A transition specifies the condition for moving from preceding steps to following steps.
    \item Represented by a horizontal line crossing vertical directional connections.
    \item Associated with a boolean variable or expression (transition condition).
    \item Control moves from the bottom of predecessor steps to the top of follower steps.
    \item Transition conditions:
    \begin{itemize}
        \item Always true: symbol \textbf{1}
        \item Can be connected via LAD/FBD networks, STL statements, or transition labels.
    \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Actions and Action Blocks}
\footnotesize
\begin{itemize}
    \item \textbf{Actions:} Operations executed while the associated step is active.
    \item Steps with no actions act as \textbf{Waiting} steps.
    \item Action connections:
    \begin{itemize}
        \item LAD left conductor rail
        \item FBD networks
        \item Action blocks
        \item STL control statements
    \end{itemize}
    \item \textbf{Action blocks:} Concisely represent complex actions and may provide a boolean feedback variable.
    \item Multiple action blocks can be connected; one boolean input controls all simultaneously.
\end{itemize}
\end{frame}

\begin{frame}{Sequence Rules}
\footnotesize
\begin{itemize}
    \item Initial state defined by active initial steps and initial variable values.
    \item Transition switching:
    \begin{itemize}
        \item Enabled if all preceding steps are active
        \item Occurs when transition condition is fulfilled
    \end{itemize}
    \item Switching activates following steps and resets preceding steps.
    \item Rules:
    \begin{itemize}
        \item Steps never connected directly; always separated by a transition
        \item Transitions never connected directly; always separated by a step
    \end{itemize}
    \item Simultaneous chains: multiple steps activated at the same time, indicated by twin horizontal lines.
\end{itemize}
\end{frame}
