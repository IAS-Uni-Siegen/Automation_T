\begin{frame}{Types of Processors used in Automation Systems}
    What is a Processor?
    \begin{itemize}
        \item A processor is an electronic component that executes instructions to perform tasks.
        \item It serves as the "brain" of an automation system, processing data and controlling operations.
        \item Processors can vary in complexity, speed, and functionality depending on the application.
        \item They are essential for executing control algorithms, managing communication, and interfacing with sensors and actuators.
    \end{itemize}
Types of Processors:
    \begin{itemize}
        \item Microcontrollers (MCUs)
        \item Digital Signal Processors (DSPs)
        \item Field-Programmable Gate Arrays (FPGAs)
        \item Application-Specific Integrated Circuits (ASICs)
        \item Programmable Logic Controllers (PLCs)
    \end{itemize}

\end{frame}

\begin{frame}{Introduction to basics of Industrial Automation}
\textbf{Terms}
\begin{enumerate}
    \item \textbf{Logic Control} -  assigns certain logic states of the output signals to certain states of the
 input signals with the help of boolean operations.
    \item \textbf{Sequence Control} - a control method with an inevitably stepwise sequence, in which the
 transition from one step to the following step(s) according to the program takes place
 depending of transition conditions.
    \item \textbf{Program of a Control} - Complete set of instructions and declarations to process signals and 
control a system (or plant) so it behaves as required.
\end{enumerate}
\textit{Remark}: This definition is valid independently of the signal processing being
 connection oriented or memory programmed.
\end{frame}

\begin{frame}{Definitions regarding program implementation}
\begin{enumerate}
    \item \textbf{Connection oriented control} - control program is defined by the
    type of the functional units and by their  connections.
    \begin{itemize}
        \item \textbf{Control with fixed program} - a connection oriented control, where program
        modifications are not planned.
        \item \textbf{Reprogrammable control} - a connection oriented control, where program
        modifications are provided for and are easy to carry out.
    \end{itemize}

    \item \textbf{Programmable logic control} - control program is stored in a
    program memory.
    \begin{itemize}
        \item \textbf{Freely programmable control} - a programmable logic control with read/write
        memory (RAM) as programm memory, whose entire content can be modified even in
        arbitrarily small extent without mechanical intervention into the control device.
        \item \textbf{Control with replaceable program} - a programmable logic control with read-only
        memory (ROM) as program memory, whose content can be modified after programming being once completed 
        only by a mechanical intervention into the control device.
    \end{itemize}
\end{enumerate}
\end{frame}

\begin{frame}{Definitions regarding control hierarchy}
\begin{enumerate}
    \item \textbf{Individual control, drive control} – a functional unit for the control of a 
    single control element or a drive.
    \begin{itemize}
        \item \textbf{Individual control level, drive control level} – summarizes all parts 
        of a control system that act directly on the process 
        by means of final control elements or drives.
    \end{itemize}

    \item \textbf{Group control} – a functional unit for the control of a 
    coherent process part, which is above associated individual or drive controls.
    \begin{itemize}
        \item \textbf{Group control level} – summarizes all parts of 
        the control unit that act on certain partitions of the individual control level.  
    \end{itemize}

    \item \textbf{Process control} – a functional unit above the 
    the group controls responsible for the control of the entire process.
    \begin{itemize}
        \item \textbf{Process control level} – summarizes all parts of 
        the control unit that act on the group control level.
    \end{itemize}
\end{enumerate}
\end{frame}


\begin{frame}{Software of PLC devices}
    \textbf{Organization of operational software}\\
    For structuring of the software in PLC devices so called blocks or program organization
    entities (POEs) are employed. 
    The block types are separated into
    \begin{itemize}
        \item  Organizational blocks (OB)
        \item Function blocks (FB) and functions (FC)
        \item Data blocks (DB)
        \item System functions (SFC) and system function blocks (SFB)
    \end{itemize}
    A block is a part of the application program grouped by function, structure, 
    or purpose. There are:
    \begin{itemize}
      \item Code blocks (OBs, FCs, FBs) that contain instructions for data processing
      \item Data blocks (DBs) that store data
    \end{itemize}
    Some organizational blocks (OBs) form the interface between the application program and 
    the system program. They are triggered by the system and contain user-written code. 
    By placing code in specific OBs, the user determines whether it runs cyclically, on a 
    timer, or in response to an alarm.
\end{frame}

\begin{frame}{Program Blocks Overview}
\begin{enumerate}
    \item \textbf{Organizational Blocks (OBs)}  
    Interface between system program and application program. They are called by the operating system and determine:
    cyclical and alarm-controlled execution, startup behavior, error handling.
    OBs are divided into:
    \begin{itemize}
        \item \textbf{System-called OBs}: control program flow, startup, and error response; user programs these.
        \item \textbf{Integrated special functions}: built-in system functions called when needed by the application.
    \end{itemize}

    \item \textbf{Functions (FCs)}  
    Code blocks \emph{without memory}. They are parameterizable and return a value to the calling block.

    \item \textbf{Function Blocks (FBs)}  
    Code blocks \emph{with memory}. Used for recurring or complex tasks (e.g., digital logic, sequences, closed-loop control). They can be called multiple times with different parameters.

    \item \textbf{Data Blocks (DBs)}  
    Contain fixed or variable data used by the program. They hold no executable code. Data may include:
    bit patterns, numeric values, text, various data types.

    \item \textbf{System Functions (SFCs) and System Function Blocks (SFBs)}  
    Prefabricated operating-system blocks for tasks such as communication or built-in system operations.
\end{enumerate}
\end{frame}

\begin{frame}{Process Image Table}
    \textbf{Process Image of Inputs (PII)}
    \begin{itemize}
        \item At the start of every cycle, all input states are scanned.
        \item These values are stored in the Process Image Input table.
        \item During program execution, the PLC uses the stored values.
        \item Ensures consistent input data throughout the cycle.
    \end{itemize}

    \vspace{0.3cm}

    \textbf{Process Image of Outputs (PIO)}
    \begin{itemize}
        \item Output values written by the program are stored in the PIO table.
        \item At the end of the cycle, the table is copied to actual outputs.
        \item Then a new cycle begins.
    \end{itemize}
\end{frame}

\begin{frame}{Cyclic Processing in PLC}
    \begin{columns}
    \column{0.5\textwidth}
    In a programmable logic controller (PLC), the program usually runs in a cycle (loop).
    \begin{itemize}
        \item PLC programs normally run in a \textbf{cyclic loop}.
        \item After switching on, the PLC executes a \textbf{start-up block} once.
    \end{itemize}

    \vspace{0.3cm}

    \textbf{Cyclic Program Scan}
    \begin{enumerate}
        \item Start at the \textbf{top of the main program} (e.g., Siemens: OB1).
        \item Execute each instruction \textbf{sequentially} to the end.
        \item Run internal \textbf{system routines}.
        \item Restart from the \textbf{top of the program}.
    \end{enumerate}

    \vspace{0.3cm}

    \column{0.5\textwidth}
    \centering
    \includegraphics[scale=0.5]{fig/lec04/cyclical_processing.pdf}
    \end{columns}
\end{frame}


\begin{frame}{Cyclic Processing in PLC}
    \textbf{Program Blocks}
    \begin{itemize}
        \item Functions and function blocks can be called inside the main block.
        \item Nested calls are possible (depth depends on the PLC manufacturer).
    \end{itemize}

    \vspace{0.3cm}

    \textbf{Processing Time (Scan Time)}
    \begin{itemize}
        \item Total cycle time = sum of processing times of all called blocks. \\
        $T_{cyc} = T_{read\_PII} + T_{exec\_prog} + T_{write\_PIO} + T_{overhead}$ \\
        where, $T_{exec\_prog}$ = sum of execution times of all blocks called in the cycle, $T_{read\_PII}$ = time to read process image of inputs, $T_{write\_PIO}$ = time to write process image of outputs, $T_{overhead}$ = additional overhead time.
        \item If a block is called $n$ times, its time is counted $n$ times.
    \end{itemize}
\end{frame}


\begin{frame}{Interrupts in Cyclical Processing}
    \textbf{Cyclical program processing can be interrupted by:}
        \begin{itemize}
            \item \textbf{Alarm processing}
                  \begin{itemize}
                  \item The normal cycle is interrupted by an external or internal interrupt signal.
                  \item The PLC executes a special block (Interrupt Service Routine).
                  \item Allows immediate reaction to important process events.
                  \item After finishing, the PLC returns to the point where it was interrupted.
                  \end{itemize}
            \item \textbf{Time-controlled processing}
                  \begin{itemize}
                  \item An internal clock triggers an interrupt at defined time intervals.
                  \item The PLC runs a specific time-controlled program block.
                  \item After execution, the PLC returns to the normal cycle.
                  \item Often used in closed-loop control tasks requiring precise timing.
                  \end{itemize}
            \item \textbf{Programming failures and device failures}
            \item \textbf{Signals from the hardware}
            \item \textbf{Change of mode of operation} 
            \begin{itemize}
                \item Caused by the device's mode switch
                \item Or by the programming tool
            \end{itemize}
        \end{itemize}
\end{frame}

\begin{frame}{Building blocks of PLC: RS Flip-Flop}

\textbf{RS Flip-Flop:}
    \begin{columns}
    \column{0.55\textwidth}
    A R/S flip flop is a storing function with two input variables R and S and an output variable
    Q, where the value Q = 1  belongs to the input states R = 0 and S = 1 and Q = 0 belongs to
    the input states R = 1 and S = 0

    \vspace{0.3cm}
    \centering
          \begin{tabular}{c c c}
          \hline
          R & S & $Q_{k+1}$ \\
          \hline
          0 & 0 & $Q_k$ \\
          0 & 1 & 1 \\
          1 & 0 & 0 \\
          1 & 1 & 0 (R has priority) \\
          \hline
        \end{tabular}

    \column{0.5\textwidth}

\begin{frame}{Building blocks of PLC: RS Flip-Flop}
    \begin{columns}
    \column{0.55\textwidth}
    \textbf{Priority rules:}
    \begin{itemize}
        \item If \textbf{R has priority}: $R=1$ dominates and forces $Q=0$.
        \item If \textbf{S has priority}: $S=1$ dominates and forces $Q=1$.
    \end{itemize}

    \vspace{0.3cm}

    \textbf{In PLC software:}
    \begin{itemize}
        \item Priority is determined by the \textbf{order of instructions}.
        \item The instruction processed \textbf{last} determines the final result.
    \end{itemize}

\begin{frame}{Building blocks of PLC: Compare and Arithmetic Operations}
\footnotesize
\begin{itemize}
    \item \textbf{Compare operations:} $<$, $>$, $\leq$, $\geq$, ==, $\neq$
    \begin{itemize}
        \item Result: Boolean variable
        \item Can be used in binary operations or control program flow
    \end{itemize}
    \item \textbf{Basic arithmetic:} ADD, SUB, MUL, DIV
    \begin{itemize}
        \item SIEMENS: $+$, $-$, $*$, $/$ with type specifier: I (INT), D (DINT), R (REAL)
        \item Fixed-point multiplication: width doubles (INT 16-bit $\times$ INT 16-bit $\rightarrow$ DINT 32-bit)
        \item Division: result type = Dividend type
        \item Floating point: watch exponent overflow
        \item Always handle division by 0
    \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Building blocks of PLC: Load, Assignment and Organizational Functions}
\footnotesize
\begin{itemize}
    \item \textbf{Load operations:} L or LD
    \begin{itemize}
        \item Provides input variable for an operation
    \end{itemize}
    \item \textbf{Assignment / Transfer:} T or ST
    \begin{itemize}
        \item Assign value to a variable, e.g., accumulator
        \item Can also be implemented with `=`
    \end{itemize}
    \item \textbf{Organizational functions:} Branching
    \begin{itemize}
        \item Conditional/unconditional based on RLO or internal status
        \item Syntax examples: SPA [label], SPB [label], SPO [label]
    \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Building blocks of PLC: Shift Functions and Type Conversions}
\footnotesize
\begin{itemize}
    \item \textbf{Shift and rotate operations:}
    \begin{itemize}
        \item Shift left/right, rotate left/right on accumulator or memory
        \item Examples: SLW 3 (shift left word by 3 bits), SRW 5 (shift right words by 5 bits), RLD 6 (rotate left word by 6 bits)
    \end{itemize}
    \item \textbf{Type conversions:}
    \begin{itemize}
        \item BTI: BCD $\rightarrow$ INT
        \item ITB: INT $\rightarrow$ BCD
        \item DTR: Fixed-point $\rightarrow$ Floating-point
        \item RND: Floating-point $\rightarrow$ Fixed-point
    \end{itemize}
\end{itemize}
\end{frame}


\begin{frame}{Building blocks of PLC: Statement List (STL) - Control Statements}
\footnotesize
\begin{itemize}
    \item A statement list consists of multiple control statements.
    \item Each control statement:
    \begin{itemize}
        \item Starts on a new line
        \item Contains an \textbf{operator} (optionally with a modifier)
        \item May contain one or more operands, separated by commas
        \item May include a preceding label followed by a colon (:)
        \item May include a comment at the end of the line
    \end{itemize}
    \item Blank lines can be inserted between statements
    \item For binary operands, the pre-occupation of Result of Logic Operation (RLO) can be done by the first statement of an AND or OR operation
    \item \textbf{Note:} Nested logic (use of `(` and `)`) requires a stack of RLOs
\end{itemize}
\end{frame}

\begin{frame}{Building blocks of PLC: Operations, Modifiers, and Operands}
\footnotesize
\begin{itemize}
    \item Default semantics: 
    \[
    \text{RLO} = \text{RLO OP Operand}
    \]
    where RLO = result of the preceding logic operation.
    \item Example: 
    \begin{itemize}
        \item Statement: \texttt{A "Value"}  
        \item Interpreted as: \texttt{RLO = RLO AND "Value"}
    \end{itemize}
    \item Modifier \texttt{N}: boolean negation of the operand
    \begin{itemize}
        \item Statement: \texttt{AN "INPUT\_1"}  
        \item Interpreted as: \texttt{RLO = RLO AND NOT("INPUT\_1")}
    \end{itemize}
    \item Modifier \texttt{(}: suspend processing until \texttt{)} occurs
    \begin{itemize}
        \item Statements: \\
        \texttt{A(} \newline
        \texttt{O "INPUT\_2"} \newline
        \texttt{O "INPUT\_3"} \newline
        \texttt{)}
        \item Interpreted as: \texttt{RLO = RLO AND ("INPUT\_2" OR "INPUT\_3")}
    \end{itemize}
    \item Modifier \texttt{C} (conditionally): statement processed only if previous RLO = 1 (or 0 if combined with N-modifier)
\end{itemize}
\end{frame}

\begin{frame}{LAD (Ladder Diagram)}
\begin{itemize}
    \item A \textbf{LAD program} provides processing, testing, and modification of data using standardized graphical symbols.
    \item These symbols are arranged in \textbf{networks} that resemble the rungs of a relay logic diagram.
    \item LAD networks are bounded on the left and right by \textbf{conductor rails}.
\end{itemize}
\end{frame}


\begin{frame}{Conductor Rails and Connection Elements}
\begin{itemize}
    \item A LAD network is bounded by vertical lines called \textbf{conductor rails}:
    \begin{itemize}
        \item \textbf{Left conductor rail}: mandatory, state is \textbf{ON} unless connected to an inactive step
        \item \textbf{Right conductor rail}: optional, no defined state
    \end{itemize}
    \item \textbf{Connection elements} are horizontal or vertical lines:
    \begin{itemize}
        \item States: \textbf{ON} (1) or \textbf{OFF} (0)
        \item \textbf{Horizontal lines}: transfer state from left to right
        \item \textbf{Vertical lines}: state = OR of all connected left horizontal lines
        \begin{itemize}
            \item \textbf{OFF}: all left lines OFF
            \item \textbf{ON}: at least one left line ON
        \end{itemize}
        \item Vertical line state determines all horizontal lines on the right
        \item States are \textbf{not copied} to lines on the left
    \end{itemize}
\end{itemize}
\end{frame}


\begin{frame}{Scan Operations and Assignment Operations}
\begin{itemize}
    \item \textbf{Scan Operations (Contacts)}:
    \begin{itemize}
        \item Pass the state of the horizontal connection on the left to the right.
        \item Only passes the state if the associated boolean input, output, or memory variable is \textbf{ON}.
        \item Does \textbf{not} change the state of the boolean variable itself.
    \end{itemize}
    \item \textbf{Assignment Operations (Coils)}:
    \begin{itemize}
        \item Copy the state of the left-hand connection to the right-hand connection.
        \item Update the associated boolean variable with the left-hand connection state.
        \item No modification to the signal occurs; the coil reflects the left-hand state.
    \end{itemize}
\end{itemize}
\end{frame}

%------------------------------------------------
\begin{frame}{Digital Signal Processing: Overview}
  \begin{itemize}
    \item \textbf{Goal of DSP:} Process real–world signals (speech, audio, images, biomedical, radar, etc.) after converting them into discrete–time, discrete–amplitude sequences.
    \item In early electronics, processing was done in the \textbf{analogue} domain:
          \begin{itemize}
            \item Direct amplification, filtering, modulation using RLC circuits, op-amps, etc.
            \item Performance limited by component tolerances, ageing, temperature drift and noise.
          \end{itemize}
    \item \textbf{Digital implementation}:
          \begin{itemize}
            \item Signals are converted to digital form via A/D conversion.
            \item Processing is carried out using algorithms on DSP processors, microprocessors or FPGAs.
            \item Advantages: programmability, reproducibility, ease of design changes, robustness to ageing and environmental variations.
          \end{itemize}
    \item Target: introduce DSP concepts that affect hardware implementation and prepare ground for FPGA-based realizations.
  \end{itemize}
\end{frame}

%------------------------------------------------
\begin{frame}{DSP Hardware Platforms}
  \begin{itemize}
    \item \textbf{General-purpose microprocessors}
          \begin{itemize}
            \item Flexible, but not optimized for real-time multiply–accumulate intensive tasks.
          \end{itemize}
    \item \textbf{Dedicated DSP microprocessors}
          \begin{itemize}
            \item Special hardware: MAC units, hardware loop controllers, addressing modes for circular buffers.
            \item Ideal for audio, communications, control applications.
          \end{itemize}
    \item \textbf{FPGAs}
          \begin{itemize}
            \item Highly parallel, reconfigurable fabric; can implement custom datapaths and pipelines.
            \item Particularly suited for high-throughput, low-latency applications (e.g. baseband processing, image processing).
          \end{itemize}
    \item For FPGA implementation we must understand:
          \begin{itemize}
            \item Sampling rates and throughput requirements.
            \item Wordlength / number representation (fixed vs floating point).
            \item Algorithmic complexity (number of multiplications/additions).
          \end{itemize}
  \end{itemize}
\end{frame}
%------------------------------------------------
\begin{frame}{Basic DSP System}
  \begin{columns}
    \column{0.55\textwidth}
      \includegraphics[width=\textwidth]{fig/lec04/Digitalisation_analogue.pdf} % Figure 2.1
    \column{0.45\textwidth}
      \begin{itemize}
        \item Analogue input is first \textbf{sampled} and \textbf{quantized} by an A/D converter.
        \item Result is a discrete-time, discrete-amplitude sequence $x(n)$.
        \item The \textbf{DSP system} applies algorithms:
              \begin{itemize}
                \item Filtering, spectral analysis.
                \item Compression / coding.
                \item Detection, estimation, equalisation, etc.
              \end{itemize}
        \item Output sequence $y(n)$ is converted back to analogue via a D/A converter and reconstruction filter.
      \end{itemize}
  \end{columns}
  \vspace{0.2cm}
  \begin{itemize}
    \item Key design question: what signal processing must occur in the digital domain, and what sampling rate / resolution are required to meet system specifications?
  \end{itemize}
\end{frame}

\begin{frame}{Digitisation of Analogue Signals}
  \begin{columns}
    \column{0.5\textwidth}
      \includegraphics[width=\textwidth]{fig/lec04/dsp_digitalisation.pdf} % Figure 2.2
    \column{0.5\textwidth}
      \begin{itemize}
        \item \textbf{Sampling}: capture signal amplitude at uniform time instants $t = nT$.
        \item \textbf{Quantisation}: map continuous amplitude to discrete levels (integers).
        \item Typical digital representation:
              \[
                x(n) \in \mathbb{Z},\quad n = \ldots,-1,0,1,\ldots
              \]
        \item Trade-off:
              \begin{itemize}
                \item Higher sampling rate $\Rightarrow$ better temporal resolution, higher data rate.
                \item More quantisation bits $\Rightarrow$ higher SNR, more hardware cost.
              \end{itemize}
      \end{itemize}
  \end{columns}
  \vspace{0.2cm}
  \begin{itemize}
    \item DSP algorithms operate on these numeric sequences; the quality of digitisation sets a fundamental limit on achievable performance.
  \end{itemize}
\end{frame}
%------------------------------------------------
\begin{frame}{Sampling of Continuous-Time Signals}
  \begin{itemize}
    \item Let $x_a(t)$ be a continuous-time analogue signal.
    \item Uniform sampling with sampling period $T$ produces discrete-time sequence
          \[
            x(n) = x_a(nT), \quad -\infty < n < \infty.
          \]
    \item The sequence $\{x(n)\}$ can be viewed as:
          \begin{itemize}
            \item A list of measurements at equally spaced instants.
            \item A representation of $x_a(t)$ suitable for digital processing.
          \end{itemize}
    \item The \textbf{sampling rate} (or sampling frequency) is
          \[
            f_s = \frac{1}{T} \quad \text{[samples/second]}.
          \]
    \item Key issue: how large must $f_s$ be so that $x_a(t)$ can be reconstructed (approximately) from $x(n)$?
  \end{itemize}
\end{frame}
%------------------------------------------------
\begin{frame}{Nyquist–Shannon Sampling Theorem}
  \begin{itemize}
    \item Assume $x_a(t)$ is bandlimited: its continuous-time Fourier transform $X_a(f)=0$ for $|f| > f_m$.
    \item \textbf{Sampling theorem:}
          \begin{block}{}
            Perfect reconstruction of $x_a(t)$ from uniform samples is possible if
            \[
              f_s \geq 2 f_m.
            \]
            The minimum sampling rate $f_s = 2 f_m$ is the \textbf{Nyquist rate}.
          \end{block}
    \item If $f_s < 2 f_m$, high-frequency components fold back into low frequencies (\textbf{aliasing}).
    \item Practical implication:
          \begin{itemize}
            \item Use analogue \emph{anti-aliasing filters} before the ADC to limit bandwidth to $f_m$.
            \item Select $f_s$ taking into account non-ideal filter roll-off and system margins.
          \end{itemize}
  \end{itemize}
\end{frame}

\begin{frame}{Sampling Examples: Speech, Music, EEG}
  \begin{itemize}
    \item \textbf{Speech}
          \begin{itemize}
            \item Most energy below $\approx 4$ kHz; standardized sampling at 8 kHz.
            \item Higher harmonics above $\approx 4$ kHz contribute little to intelligibility.
          \end{itemize}
    \item \textbf{Music}
          \begin{itemize}
            \item Human hearing up to $\approx 20$ kHz.
            \item CD audio uses 44.1 kHz $\Rightarrow$ Nyquist $\approx 22.05$ kHz, covering audible spectrum.
          \end{itemize}
    \item \textbf{Biomedical signals (EEG, ABR)}
          \begin{itemize}
            \item EEG bandwidth of interest often tens of Hz to a few kHz.
            \item Example: auditory brainstem response (ABR) in 100–3000 Hz range.
            \item EEG may be sampled at 20 kHz, giving Nyquist of 10 kHz for capturing fine temporal features and allowing digital filtering.
          \end{itemize}
    \item These examples illustrate how sampling rate is chosen not only from theory but also from the physics and perceptual/diagnostic needs of the application.
  \end{itemize}
\end{frame}

\begin{frame}{DSP Transformations: Time vs Frequency Domain}
  \begin{itemize}
    \item Many DSP tasks are easier in the \textbf{frequency domain}:
          \begin{itemize}
            \item Filtering, spectral analysis, modulation, compression, feature extraction.
          \end{itemize}
    \item Core transforms used:
          \begin{itemize}
            \item \textbf{Discrete Fourier Transform (DFT)} and its efficient implementation, the \textbf{FFT}.
            \item \textbf{Discrete Cosine Transform (DCT)} – real-valued transform heavily used in image/video compression.
            \item \textbf{Wavelet transforms} – multi-resolution analysis for non-stationary signals.
          \end{itemize}
    \item Hardware implications:
          \begin{itemize}
            \item These transforms are computation–intensive (many multiplications/additions).
            \item Efficient FPGA or DSP implementations rely on exploiting symmetry, periodicity and pipeline/parallel architectures.
          \end{itemize}
  \end{itemize}
\end{frame}
%------------------------------------------------
\begin{frame}{Discrete Fourier Transform (DFT)}
  \begin{itemize}
    \item For a finite-length sequence $x(n)$, $n = 0,\ldots,N-1$, the $N$-point DFT is
          \[
            X(k) = \sum_{n=0}^{N-1} x(n) W_N^{nk}, \quad k = 0,\ldots,N-1,
          \]
          where the \textbf{twiddle factor} is
          \[
            W_N = e^{-j2\pi/N}.
          \]
    \item Interpretation:
          \begin{itemize}
            \item $X(k)$ are samples of the discrete-time Fourier transform on the unit circle.
            \item Each $X(k)$ corresponds to a complex sinusoid of frequency $2\pi k/N$.
          \end{itemize}
    \item Inverse DFT:
          \[
            x(n) = \frac{1}{N}\sum_{k=0}^{N-1} X(k) W_N^{-nk}.
          \]
    \item Direct computation requires $N^2$ complex multiplications and a similar number of additions – expensive for large $N$.
  \end{itemize}
\end{frame}
%------------------------------------------------
\begin{frame}{Fast Fourier Transform (FFT)}
  \begin{columns}
    \column{0.4\textwidth}
      \includegraphics[width=\textwidth]{fig/lec04/FFT_structure.pdf} % Figure 2.5
    \column{0.55\textwidth}
      \begin{itemize}
        \item FFT algorithms exploit \textbf{symmetry} and \textbf{periodicity} in $W_N^{nk}$.
        \item Basic idea (radix-2, $N=2^m$):
              \begin{itemize}
                \item Decompose $N$-point DFT into smaller DFTs of size $N/2$, $N/4$, …, 2.
                \item Reuse intermediate results via "butterfly" computations.
              \end{itemize}
        \item Computational complexity reduced from $O(N^2)$ to $O(N\log_2 N)$.
        \item Essential for real-time spectrum analysis, OFDM communication, and many other high-speed applications.
      \end{itemize}
  \end{columns}
  \vspace{0.1cm}
  \begin{itemize}
    \item In OFDM (e.g. IEEE 802.11a), FFT/IFFT (inverse) are used to map data symbols onto many orthogonal subcarriers and recover them at the receiver.
  \end{itemize}
\end{frame}
%------------------------------------------------
\begin{frame}{Radix-2 DIT FFT: Even--Odd Decomposition}
  \begin{itemize}
    \item Start from the $N$-point DFT:
          \[
            X(k) = \sum_{n=0}^{N-1} x(n) W_N^{nk}.
          \]
    \item Split the sum into even and odd indices, $x_e(n)=x(2n)$, $x_o(n)=x(2n+1)$:
          \[
            X(k) = \sum_{n=0}^{N/2-1} x_e(n) W_N^{2nk}
                 + W_N^{k} \sum_{n=0}^{N/2-1} x_o(n) W_N^{2nk}.
          \]
    \item Use $W_N^{2nk} = W_{N/2}^{nk}$ to obtain
          \[
            X(k) = E(k) + W_N^{k} O(k),
          \]
          where $E(k)$ and $O(k)$ are $N/2$-point DFTs of $x_e$ and $x_o$.
    \item For $k+N/2$:
          \[
            X(k+N/2) = E(k) - W_N^{k} O(k), \text{giving a pair of outputs from one butterfly.}
          \]
          
    \item Recursively applying this decomposition $m=\log_2 N$ times yields the full radix-2 FFT.
  \end{itemize}
\end{frame}

%------------------------------------------------
\begin{frame}{FFT Butterfly and Implementation Notes}
  \begin{itemize}
    \item A radix-2 \textbf{butterfly} computes
          \[
            X_1 = A + W B, \qquad X_2 = A - W B,
          \]
          where $A$ and $B$ are intermediate values and $W$ is a twiddle factor.
    \item Data-flow organisation:
          \begin{itemize}
            \item \textbf{Decimation-in-time (DIT)}: split in time domain, outputs appear in bit-reversed order.
            \item \textbf{Decimation-in-frequency (DIF)}: split in frequency domain, inputs in bit-reversed order.
          \end{itemize}
    \item Hardware aspects:
          \begin{itemize}
            \item Each stage has $N/2$ butterflies; total of $(N/2)\log_2 N$ butterflies.
            \item Fixed-point implementations require careful scaling to avoid overflow.
            \item Pipeline and systolic FFT architectures exploit concurrency for high throughput.
          \end{itemize}
    \item Practical design choices:
          \begin{itemize}
            \item Power-of-two sizes for radix-2; mixed-radix FFTs for composite $N$.
            \item Use of in-place algorithms to minimise memory.
          \end{itemize}
  \end{itemize}
\end{frame}
%------------------------------------------------
\begin{frame}{Discrete Cosine Transform (DCT)}
  \begin{itemize}
    \item The 1-D DCT of a length-$N$ sequence $x(n)$ is
          \[
            X(k) = \sum_{n=0}^{N-1} x(n)\cos\left[\frac{\pi}{N}\left(n + \frac{1}{2}\right)k\right],
            \quad k = 0,\ldots,N-1.
          \]
          (Only cosine terms, so $X(k)$ is real-valued.)
    \item Widely used in image and video compression (JPEG, MPEG):
          \begin{itemize}
              \item The DCT can be viewed as the DFT of an \textbf{even extension} of $x(n)$:
                        \begin{itemize}
                          \item Reflect the sequence around the boundaries to avoid artificial discontinuities.
                          \item This leads to purely real, cosine-only basis functions.
                        \end{itemize}
            \item Enables effective \textbf{quantization} and \textbf{compression} by discarding high-frequency coefficients.
          \end{itemize}
  \end{itemize}
\end{frame}

\begin{frame}{Wavelet Transform and DWT}
  \begin{itemize}
    \item Wavelets are short-duration oscillatory functions that provide \textbf{time–frequency} localization.
    \item Wavelet decomposition:
          \begin{itemize}
            \item Decomposes a signal into shifted and scaled versions of a prototype wavelet.
            \item Very suitable for non-stationary signals where classical FFT (fixed frequency resolution) is inadequate.
          \end{itemize}
    \item \textbf{Discrete Wavelet Transform (DWT)} via filter banks:
          \begin{itemize}
            \item Input $x(n)$ is passed through a \textbf{low-pass} filter $g(n)$ and a \textbf{high-pass} filter $h(n)$.
            \item Outputs are down-sampled by 2 to produce approximation and detail coefficients:
                  \[
                    y_{\text{low}}(n) = \sum_{k=-\infty}^{\infty} x(k) g(2n-k),
                  \]
                  \[
                    y_{\text{high}}(n) = \sum_{k=-\infty}^{\infty} x(k) h(2n-k).
                  \]
            \item Process can be iterated on the low-pass branch to obtain multi-resolution representations.
          \end{itemize}
    \item Applications: image compression and denoising, biomedical signal analysis, transient detection.
  \end{itemize}
\end{frame}

\begin{frame}{Digital Filters: Overview}
  \begin{itemize}
    \item A \textbf{filter} shapes the spectral content of a signal:
          \begin{itemize}
            \item Low-pass, high-pass, band-pass, band-stop, etc.
          \end{itemize}
    \item \textbf{Analogue filters}:
          \begin{itemize}
            \item Implemented using resistors, capacitors, inductors, op-amps.
            \item Continuous-time, continuous-amplitude.
          \end{itemize}
    \item \textbf{Digital filters}:
          \begin{itemize}
            \item Implemented as algorithms operating on discrete-time sequences.
            \item Use arithmetic operations (add, multiply, delay).
            \item Very precise and stable; easily reconfigurable in software or hardware (DSP, FPGA).
          \end{itemize}
    \item Two main classes:
          \begin{itemize}
            \item Finite Impulse Response (FIR) – impulse response of finite duration.
            \item Infinite Impulse Response (IIR) – involves feedback, theoretically infinite impulse response.
          \end{itemize}
  \end{itemize}
\end{frame}
%------------------------------------------------
\begin{frame}{Finite Impulse Response (FIR) Filters}
  \begin{columns}
    \column{0.55\textwidth}
      \includegraphics[width=\textwidth]{fig/lec04/FIR.pdf} % Figure 2.8 or 2.7
    \column{0.45\textwidth}
      \begin{itemize}
        \item General FIR filter of length $N$:
              \[
                y(n) = \sum_{i=0}^{N-1} a_i x(n-i).
              \]
        \item Realized using:
              \begin{itemize}
                \item Delay elements $z^{-1}$ (registers / memory).
                \item Multipliers implementing coefficients $a_i$.
                \item Adders accumulating partial sums.
              \end{itemize}
      \end{itemize}
  \end{columns}
  \vspace{0.1cm}
  \begin{itemize}
    \item FIR filters are always \textbf{bounded input bounded outout (BIBO) stable} since their impulse response is finite.
    \item With symmetric coefficients ($a_i = a_{N-1-i}$), FIR filters exhibit \textbf{linear phase}: they delay all frequency components equally, avoiding waveform distortion.
  \end{itemize}
\end{frame}
%------------------------------------------------
\begin{frame}{LTI Properties and FIR Structures}
    \begin{columns}
    \column{0.6\textwidth}
  \begin{itemize}
    \item An FIR filter (or any digital filter) is \textbf{linear} and \textbf{time-invariant} if it satisfies:
          \begin{itemize}
            \item \textbf{Superposition}: response to $x_1(n)+x_2(n)$ is $y_1(n)+y_2(n)$.
            \item \textbf{Homogeneity}: response to $c\,x(n)$ is $c\,y(n)$.
            \item \textbf{Shift invariance}: shift in input produces equal shift in output.
          \end{itemize}
    \item These properties enable:
          \begin{itemize}
            \item Convolution description of filtering.
            \item Use of frequency response $H(e^{j\omega})$ to characterise behavior.
          \end{itemize}
    \item FIR filters can be combined:
          \begin{itemize}
            \item \textbf{Cascade} structure: output of one filter is input to the next.
            \item \textbf{Parallel} structure: inputs processed by multiple filters, then summed.
          \end{itemize}
  \end{itemize}
    \column{0.4\textwidth}
      \includegraphics[width=0.7\textwidth]{fig/lec04/FIR_config.pdf} % Figure 2.9(a)

      \includegraphics[width=0.7\textwidth]{fig/lec04/FIR_config.pdf} % Figure 2.9(b)
  \end{columns}
\end{frame}

\begin{frame}{Low-Pass FIR Filter Specifications}
  \begin{columns}
    \column{0.45\textwidth}
      \includegraphics[width=\textwidth]{fig/lec04/FIR_spec.pdf} % Figure 2.10
    \column{0.55\textwidth}
      \small
      \begin{itemize}
        \item Design starts from a \textbf{desired magnitude response}:
              \begin{itemize}
                \item Passband with nearly constant gain.
                \item Stopband with strong attenuation.
              \end{itemize}
        \item Key parameters:
              \begin{itemize}
                \item Passband edge frequency $f_p$.
                \item Stopband begin frequency $f_c$.
                \item Passband ripple $\delta_1$.
                \item Stopband ripple / attenuation $\delta_2$.
                \item \textbf{Transition band}: region between $f_p$ and $f_c$.
              \end{itemize}
        \item Ripple ratio: $\displaystyle \text{Ripple ratio} = \frac{\delta_2}{\delta_1}$.
        \item Example plot shows the ripples in both passband and stopband and the ideal gain level.
      \end{itemize}
  \end{columns}
  \small
  \begin{itemize}
    \item Specifications $(\delta_1,\delta_2,f_p,f_c)$ directly determine filter length and window choice.
  \end{itemize}
\end{frame}

\begin{frame}{From Ideal Response to Practical FIR Filter}
  \small
  \begin{itemize}
    \item Start with an \textbf{ideal} (infinite-length) low-pass response:
          \begin{itemize}
            \item Sharp transition; zero passband/stopband ripple.
            \item Impulse response $h_\text{ideal}(n)$ extends to $\pm\infty$.
          \end{itemize}
    \item \textbf{Design idea}:
          \begin{enumerate}
            \item Specify desired magnitude response $|H_d(\omega)|$ with given $f_p,f_c,\delta_1,\delta_2$.
            \item Compute corresponding \emph{inverse transform} to obtain $h_\text{ideal}(n)$.
            \item Truncate to a finite length $N$ and shift to make it causal.
          \end{enumerate}
    \item Simple truncation $\Rightarrow$ multiply $h_\text{ideal}(n)$ by a \textbf{rectangular window}.
          \begin{itemize}
            \item This introduces oscillations (ripples) near discontinuities in the frequency domain
                  $\Rightarrow$ \textbf{Gibbs phenomenon}.
            \item Ripples occur in both passband and stopband.
          \end{itemize}
    \item Practical design uses alternative windows (Hamming, Hann, Kaiser, Dolph–Chebyshev, …) to control ripple and transition width.
  \end{itemize}
\end{frame}

\begin{frame}{Why Window and Filter Length Matter (FIR Low-Pass)}

  \begin{block}{The message to remember (industrial relevance)}
  \textbf{Two design knobs} (window type, filter length $N$) determine \textbf{three outcomes} that directly impact
  \textbf{control/measurement quality} and \textbf{embedded implementation cost}.
  \end{block}


  \begin{block}{Two knobs you can tune}
  \begin{itemize}
  \item \textbf{Window type} (e.g., Hamming vs Dolph--Chebyshev)
  \begin{itemize}
  \item sets \textbf{sidelobes / ripple} (leakage, stopband attenuation)
  \item influences \textbf{transition sharpness} (mainlobe width)
  \end{itemize}
  \item \textbf{Filter length $N$} (number of taps)
  \begin{itemize}
  \item larger $N$ $\Rightarrow$ \textbf{narrower transition band}
  \item larger $N$ $\Rightarrow$ \textbf{lower ripple} (for same window)
  \end{itemize}
  \end{itemize}
  \end{block}

\end{frame}


\begin{frame}

  \begin{block}{Three outcomes to practice}
  \begin{itemize}
  \item \textbf{Signal quality:} noise rejection vs distortion
  \begin{itemize}
  \item ripple/leakage $\Rightarrow$ residual noise, spectral leakage
  \item too-wide transition $\Rightarrow$ poor selectivity
  \end{itemize}
  \item \textbf{System behavior:} delay and closed-loop impact
  \begin{itemize}
  \item FIR group delay $\approx \frac{N-1}{2}$ samples (linear phase)
  \end{itemize}
  \item \textbf{Compute and memory:} feasibility on MCU/FPGA/PLC
  \begin{itemize}
  \item cost $\propto N$ multiplies/adds per sample (+ coefficient memory)
  \end{itemize}
  \end{itemize}
  \end{block}

  \begin{alertblock}{Rule-of-thumb decision}
  \begin{itemize}
  \item Need \textbf{sharper cutoff}? \ \textbf{Increase $N$} (most reliable).
  \item Need \textbf{more stopband attenuation}? \ \textbf{Change window} (then adjust $N$ if needed).
  \item Need \textbf{lower cost/latency}? \ \textbf{Reduce $N$} and accept wider transition / less attenuation.
  \end{itemize}
  \end{alertblock}
\end{frame}

\begin{frame}{Motivation for IIR Filters}
  \small
  \begin{itemize}
    \item FIR filters are simple and robust, but:
          \begin{itemize}
            \item Require many taps to achieve very sharp cut-off.
            \item Computational cost increases linearly with filter length.
          \end{itemize}
    \item \textbf{Infinite Impulse Response (IIR) filters} introduce feedback (recursive structure):
          \begin{itemize}
            \item Can approximate analogue filter characteristics (Butterworth, Chebyshev, Elliptic) with far fewer coefficients.
            \item Sharper transition for a given order compared to FIR.
          \end{itemize}
    \item Main trade-offs:
          \begin{itemize}
            \item Possible \textbf{non-linear phase} (phase distortion).
            \item Susceptible to \textbf{stability} and \textbf{quantisation} issues due to feedback.
          \end{itemize}
    \item Design approach:
          \begin{itemize}
            \item Often start from a well-known analogue prototype $H_A(s)$.
            \item Transform into digital $H_D(z)$ using mappings such as impulse invariance, $z$-transform, or bilinear transform.
          \end{itemize}
  \end{itemize}
\end{frame}
%------------------------------------------------
\begin{frame}{Direct-Form IIR Structure}
  \begin{columns}
    \column{0.55\textwidth}
      \includegraphics[width=\textwidth]{fig/lec04/IIR_direct.pdf} % Figure 2.12
    \column{0.45\textwidth}
      \small
      \begin{itemize}
        \item General IIR difference equation:
              \[
                y(n) = \sum_{i=0}^{N-1} a_i x(n-i) + \sum_{j=1}^{M-1} b_j y(n-j).
              \]
        \item Corresponding transfer function:
              \[
                H(z) = \frac{\sum_{i=0}^{N-1} a_i z^{-i}}{1 - \sum_{j=1}^{M-1} b_j z^{-j}}.
              \]
        \item Realisation:
              \begin{itemize}
                \item Feedforward path: FIR-like part with coefficients $a_i$.
                \item Feedback path: uses previous outputs scaled by $b_j$.
              \end{itemize}
      \end{itemize}
  \end{columns}
  \vspace{0.1cm}
  \small
  \begin{itemize}
    \item Direct-form structures are straightforward but can be sensitive to coefficient quantisation and round-off noise, especially for high-order filters.
  \end{itemize}
\end{frame}

\begin{frame}{Wave Digital Filters (WDFs): Concept}
  \small
  \begin{itemize}
    \item WDFs form a special class of digital filters derived from classical analogue \textbf{lattice/ladder} networks.
    \item Basic idea:
          \begin{itemize}
            \item Express analogue circuit in terms of \emph{wave variables} (incident and reflected waves at ports).
            \item Map each analogue element (resistor, capacitor, inductor) to a corresponding digital adaptor.
          \end{itemize}
    \item Advantages:
          \begin{itemize}
            \item Very \textbf{low sensitivity} to coefficient quantisation and round-off.
            \item Good control of losses and passband/stopband attenuation.
            \item Structures are well suited for fixed-point implementation with limited wordlength.
          \end{itemize}
    \item Frequency response of WDFs preserves key properties of the original analogue network, while also benefiting from digital flexibility.
  \end{itemize}
\end{frame}

\begin{frame}{DSP in a Nutshell: From Signals to Implementations}
  \begin{itemize}
    \item \textbf{Start: real-world signals}
          \begin{itemize}
            \item Continuous-time, continuous-amplitude (speech, audio, images, biomedical, radar).
            \item Sampled and quantised $\Rightarrow$ discrete-time sequences $x(n)$ for digital processing.
          \end{itemize}

    \item \textbf{Analyse in the transform domain}
          \begin{itemize}
            \item DFT/FFT: complex exponential basis, efficient $O(N\log N)$ spectrum computation.
            \item DCT: cosine-only basis with strong energy compaction (JPEG/MPEG).
            \item Wavelet/DWT: multi-resolution time–frequency analysis for non-stationary signals.
          \end{itemize}

    \item \textbf{Shape spectra using digital filters}
          \begin{itemize}
            \item FIR filters: convolution with finite $h(n)$, always bounded input, bounded output stability (BIBO) stable, linear phase with symmetric taps.
            \item IIR filters: recursive structures with poles/zeros; sharp responses with low order but care needed for stability and quantisation.
            \item Design from specifications $(\delta_1,\delta_2,f_p,f_c)$ via windows, analogue prototypes, bilinear transform, etc.
          \end{itemize}
  \end{itemize}
\end{frame}

\begin{frame}{DSP in a Nutshell: From Signals to Implementations}          \begin{itemize}
\item \textbf{Map mathematics to hardware/software}
          \begin{itemize}
            \item Realisation as structures of adds, multiplies and delays on DSPs, FPGAs or ASICs.
            \item FFT pipelines, FIR/IIR direct forms, second-order sections, and wave digital filters for robust fixed-point implementation.
          \end{itemize}

    \item \textbf{Big picture}
          \begin{itemize}
            \item DSP provides a toolbox: \emph{sample} $\rightarrow$ \emph{transform} $\rightarrow$ \emph{filter / modify} $\rightarrow$ \emph{reconstruct}.
            \item Design choices (transform, filter type, structure) are driven by application constraints: accuracy, complexity, latency and implementation platform.
          \end{itemize}
\end{itemize}
